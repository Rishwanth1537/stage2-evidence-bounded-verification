# SCOUT 1: Prior work on verifying / guarding tool calls and their arguments

Prepared 2026-10-16. Scope: read-only literature and repository scout; no other project file was edited.
Method: `curl` plus small Python scripts against arxiv.org search/abs/pdf pages (text extracted with pypdf), the GitHub REST search and readme endpoints, and the Hugging Face dataset search API. WebSearch/WebFetch were not used. Semantic Scholar was not used.

**Reading-depth labels used in every table.** `FULL(sections)` = I read those sections of the extracted PDF text. `ABSTRACT` = the arXiv abs page only (numbers are the authors' own, unreplicated). `README` = the GitHub README (not the code, nothing was run). `SNIPPET` = search-result description only. Anything I only saw cited inside another paper is NOT cited as a source here; it is listed in section 6 as unverified.

## 0. Bottom line for the professor's challenge

1. **The question "can an LLM judge do this" is already an active literature, and it is the closest competitor.** Ma et al. (arXiv 2610.18497, 13 Oct 2026, three days old) study exactly "argument-level judges for tool calls", including a benchmark (FinTrace-derived) whose wrong calls are produced by changing one argument by rule, the same protocol as our injected single-argument errors. Off-the-shelf judges (plain truncated input) already reach 83.36 to 89.31 argument AUROC on that FinTrace-derived set, and up to 91.95 on FC-RewardBench (section 4). So we cannot claim "an LLM cannot do this". We must run a judge panel.
2. **That same paper is also the strongest evidence for a dedicated checker.** All seven judges it tests accept correct values less often when no text in their input states the value (the "derivation gap", 22.67 to 36.13 points on two benchmarks). Judges prefer a visible wrong value to a hidden correct one. This is a failure of exactly the kind a provenance/typed-matching checker over the full history is built to avoid.
3. **Three of our ingredients already exist elsewhere and must not be claimed as novel:** the weakest-argument call score (it is the paper's own aggregation, `min` over argument scores), the "tool call must be traceable to context" framing (ProvenanceGuard, ASE 2026), and deterministic normalised/fuzzy argument grounding against the conversation (an open-source library, Saidso, README only). The split-conformal false-alarm budget is also an established technique (E-valuator, CORA) but I found no one applying it to argument-level value grounding.
4. **The defensible gap is the combination plus the evaluation:** a deterministic, millisecond-cost, typed-normaliser grounding score with a calibrated false-block budget, compared head-to-head with an LLM judge panel at matched false-block rate, with an error-independence measurement. I found none of that in one place.

## 3. Top 5 closest competitors and exactly how we differ

**1. Ma et al., DeRef and the argument-judge study (2610.18497).**
What it already does: argument-level verification of tool calls, call score = `min` over argument scores (so "call score = weakest argument" is not ours), injected single-argument errors on FinTrace-derived data, and a systematic judge panel including 4B to 27B LLMs and two cheap scoring models. They also show how to fix a judge's blind spot (candidate-blind reference derivation, +1.4 to +22.1 AUROC).
What we can still claim: a typed deterministic matcher over the full history needs no derived reference for values that appear in the history, costs no GPU, and can be given a conformal false-block budget; their threshold rule (accept 80% of correct arguments) offers no guarantee on a new distribution. What we cannot claim: that LLM judges are weak on injected errors. Their plain 27B judge scores 89.31 argument AUROC on the rule-injected FinTrace data (Table 2).
Honest caution: if the injected errors in Glaive are mostly value substitutions with a visible source, a strong judge may match us; the gap appears only for out-of-view, defaulted or inferred values.

**2. ProvenanceGuard (She et al., 2607.01236).**
Already does: pre-execution check that parameters are "traceable to the context", framed as provenance, with a head-to-head against an LLM-as-judge baseline. We cannot claim the grounding framing.
Differs: all stages are LLM calls (3.6 calls, 2.9 to 7.5 s per case); no typed normalisers; no calibrated false-block budget; evaluated on agent-safety and WorkBench traces where the unit is "misaligned trace", not injected single-argument errors. Our value-level typed check is a different mechanism, and a fair comparison is "ProvenanceGuard prompt with a small LLM" as a baseline.

**3. Saidso (repo, README only).**
Already does: deterministic argument grounding against the conversation with normalised and fuzzy matching, tool-output provenance, retraction handling, steer-back and attestation, microsecond latency (their number). This is the closest implementation of our mechanism. Plainly: the mechanism is not novel as software. Our contribution over it has to be (a) a measured detection and false-block evaluation, (b) split-conformal calibration, (c) MCP-server packaging and (d) comparison with LLM judges. I did not install it, so I do not know its accuracy; running it on our Glaive set as a baseline is a cheap, strong move.

**4. Latent Critic (Vijayvargiya and Lokesh, 2608.10430).**
Already does: parameter-level specification-grounding detection before execution, defined against the dialogue history, with localisation and a recall at 1% false-positive-rate number. Differs: white-box (needs hidden states of the same model), trained, labels from a simulator; ours is black-box, training-free and model-agnostic. It supplies a reference number: 38.7% recall at 1% FPR for the learned critic and 28.3% for a fine-tuned 4B judge, on a harder, model-generated error distribution than ours. Its error analysis (partial grounding of "2 PM" with the date fabricated) names a case our typed normalisers can handle explicitly.

**5. Agent-Sentry (2603.22868) and its cluster (PACT 2605.11039, ToolFence 2609.37196).**
Already do: argument-provenance-aware, cascaded monitors where a deterministic value check runs first and an LLM judge only sees the residual. Differ: they defend against injection and unauthorised arguments (AgentDojo), not against wrong or invented values, and report utility/security trade-offs rather than a calibrated false-block budget. Our novelty claim must be explicitly scoped to "value hallucination/wrong value", not "argument provenance".

**Calibration ingredient (not a competitor to the checker, but to the "false-block budget" claim):** E-valuator (2512.03109) and CORA (2604.09155) already turn arbitrary verifier or risk scores into decision rules with a user-set error budget, and SafeCommit (2608.04289) uses a conformal action certificate. I found no paper that applies split-conformal thresholds to argument-level value grounding; I could not prove none exists.

## 4. Evidence on "LLM judges versus dedicated or deterministic checkers"

### 4.1 Evidence that LLM judges are good enough, or that a cheap judge is hard to beat
- Ma et al. (2610.18497) Table 2, plain truncated input, argument AUROC on FCRB / CFB / FinTrace: Jev 90.83 / 75.01 / 89.11; Qwen3.8-27B 91.95 / 78.92 / 89.31; Qwen3-8B 78.79 / 66.79 / 85.15; CLM 72.51 / 63.41 / 83.36. With DeRef: Qwen3.8-27B 93.39 / 95.09 / 92.25. FinTrace wrong values are made by rule changing one argument, i.e. close to our injection protocol. Strong judges are therefore a serious baseline.
- Judge cost can be tiny: in the same paper (Table 13) CLM and Qwen3-8B score a DeRef-style input in 8 to 67 ms per input on one GPU (batch size 1, excluding the deriver); JEV-as-a-Judge (2609.26550, abstract) reports 0.15 s median latency at 0.36% of a frontier judge's fee, and within three points of GPT-6 when the verdict can be read off the text. A pure speed argument is therefore weak against a small decision-model judge (it holds against thinking judges and multi-stage pipelines: Qwen3.8-27B with thinking took 2.00 to 7.46 s per input; the deriver 2.44 to 7.27 s per reference).
- Trained verifiers help: ToolRM (2509.11963) and ToolPRM (2510.14703) report gains over general-purpose baselines (abstracts only); the fine-tuned 4B external judge in Latent Critic reaches 0.915 AUROC.
- ProvenanceGuard shows that structuring an LLM check lowers misses sharply: average error rate on misaligned traces 44.3% (direct prompt) to 14.7% (provenance prompt) to 2.1% (multi-stage) on Agent-SafetyBench (11 LLMs). The benefit is smaller on WorkBench (32.4% to 20.9% to 18.7%) and absent for GPT-5 and Claude-sonnet-4.6 there.

### 4.2 Evidence that a separate or deterministic checker still adds value
- **Judges track visible text, not truth** (2610.18497): correct values with no visible reference are accepted less often by all seven judges, by 22.67 to 36.13 points (CFB and FinTrace, pooled out-of-view paths), for 4B through 27B alike. On the controlled relocation test, burying the correct source drops AUROC from 91.89 to 99.88 down to 39.80 to 49.03, and every judge ranks the visible wrong value above the hidden correct one. Swapping the value inside a reference text flips decisions (acceptance of correct values falls by 15.36 to 57.07 points). This is what an exact or typed matcher over the full history does by construction, and where we should win.
- **The same paper warns about us:** a correct DEFAULT, inferred or history-only value has no matching span, so a grounding checker can false-block exactly the cases judges struggle with. Its call-level appendix also finds `min` aggregation raises call AUROC by 8.15 to 16.21 points on FCRB, but adds nothing on CFB (-3.04 to +1.22), where the gap is large.
- **Without a reference, judges over-credit:** 2607.12885 (flip rates up to 85% when a reference is added), 2503.05061 (judges agree with experts mainly on questions they could answer themselves), 2601.07506 (swapped wrong references degrade grading). All ABSTRACT only and about QA grading, not tool arguments, so only indirect support.
- **A scale ceiling for judges:** AgentJudgeBench (2608.26623): on hard queries without ground truth all six judges (20B to frontier) land in a 77 to 82% band; CoT and temperature negligible; rubrics help up to +6.5 pp. The authors use a deterministic scorer as reference because LLM labels would reintroduce the reliability problem, but note it is itself only 82.5% aligned with one human on parameter structure, a caution for any strict deterministic checker.
- **Correlated errors between LLM verifiers, near-independence for a deterministic layer** (2610.07359, caveats above): two judges that each miss 10.5% alone miss 5.2% together (29 of 560) versus 1.1% predicted under independence; φ median +0.430 for judge pairs, +0.014 (not significant) for rule layer plus judge; combined layers equivalent to 1.86 to 2.09 independent layers versus 1.2 to 1.4 for two judges (STRICT miss definition). Caveat: the rule layer collapsed to a 52.9% miss rate on a held-out corpus, so independence is not robustness.
- **Evidence source matters more than verifier model** (2609.10969): swapping the verifier model lowered unsafe approvals by 11.3 pp, an independent evidence source by 40.9 pp. Implication for us, stated plainly: our checker reads the same conversation as the agent, so it does not provide evidence independence; any independence claim must rest on a different failure mechanism, and must be measured.
- **Theory and measurement of shared blind spots:** Han (2607.13918, ABSTRACT) argues a blind-spot atom caps what any number of correlated gates can add and names decorrelation (model family, modality, evidence source) as the lever; Kuai et al. (2604.07650) report significant behavioural entanglement among 18 LLMs from six families, associated with judge over-endorsement (rho 0.508 on MMLU-Pro); Tsui (2507.02778) reports a 64.5% self-correction blind spot across 14 open non-reasoning models when the same error is model-attributed rather than user-attributed. All ABSTRACT only.
- **Small decision-model guards are attackable and weak on numbers:** 2610.12292 (fail-open 0% to 63% with six irrelevant log lines; a deterministic rule over typed fields hit 100% on all six policies); 2609.39496 (Jev rejects a missing numeric answer only 7% of the time, 79% after a dev-set threshold). Both ABSTRACT only.
- **Cost and latency of LLM checking:** ProvenanceGuard about $0.011 and 2.9 to 7.5 s per case; Ma et al. thinking-judge 2.0 to 7.5 s per input; Dubey (2608.02464, ABSTRACT) says judging every step with a second LLM "costs more than the agent itself" and reports deterministic verification around 200 microseconds per step. Saidso claims about 12 microseconds per check (README, unverified).
- **Deterministic gates help even frontier models, in their domains:** 2607.07405 (+12.4 pp gpt-4o-mini; +10.4 pp gpt-5.2 with n=5, unreplicated) and NOMOS 2610.11030 (airline violations of reference-encoded clauses 66.3% to 2.6%). Both about policy, not argument grounding, and NOMOS also shows a naive gate refusing 95.9% of task-passing calls before repair.

### 4.3 Net reading for the report
The literature does NOT support "an LLM judge makes a checker useless" and does NOT support "an LLM cannot do it". The accurate statement the evidence supports is: judges are strong when the supporting text is visible in their input, collapse towards chance when it is hidden or derived, cost 10 ms to several seconds, share failures with each other, and offer scores with no false-block guarantee. A deterministic grounding checker is complementary and cheap; whether it is also better on our data is an empirical question we have not yet answered.

## 6. Gaps: what I looked for and could not find or verify

- **No head-to-head** of a deterministic typed argument-grounding checker against LLM judges at calibrated false-block rates, and no paper applying split-conformal thresholds to argument-level grounding scores. Closest: E-valuator (trajectory level), CORA and SafeCommit (action level). Absence of evidence in about 70 arXiv queries is not proof of absence.
- **Referenced but not located, therefore NOT cited as sources:** TwinCheck (Dai and Huang 2026), ToolPRMBench (Li et al., ACL Findings 2026), AgentProcessBench (Fan et al., KDD 2026), CLM (Kwok et al. 2026, Notion blog) and Jev (TypeSafe blog); I only saw them cited inside Ma et al. One arXiv query for TwinCheck returned nothing, and the ToolPRM query returned only ToolPRM (not ToolPRMBench); I did not search AgentProcessBench by title.
- **Not opened:** the DeRef code, the AgentSuite complex-func-bench trajectory dataset, any benchmark artifact links, ProvenanceGuard's code. PACT, Agent-Sentry and ToolFence were not read past the abstract (PACT partly via grep). Yang's results sections after the instrument definition were not read in full.
- **Repositories** were judged from READMEs. I did not install Saidso, so its normalisation quality and false-block behaviour are unknown. The Deconvolute "argument-level" wording is from the search snippet. McpVanguard, Cordum and PIC were skimmed only. Star counts are tiny for the closest grounding repo (Saidso, 1 star), so adoption is not evidence of quality.
- **Hugging Face dataset search** returned nothing usable for "tool call verification" style datasets; no public dataset of injected argument errors was found besides what Ma et al. derive from FinTrace and what SAAG (already known) uses.
- **Older prior art** (dialogue state tracking slot-value verification, value-grounding in task-oriented dialogue, 2015 to 2023) was only probed with a single query; a related-work section should cover it separately.
- **Most numbers above are the authors' own and from abstracts**; none was replicated. Where two sources give different scales (AUROC vs recall at FPR vs error rate on misaligned traces) they are not comparable with our 14.0% vs 7.3% false-block figures and should not be put in one table without a re-run.
- **Temporal caveat:** several of the strongest sources are a few days to weeks old (2610.07359, 2610.12292, 2610.18497) and may be revised; the DeRef paper in particular is v1.
