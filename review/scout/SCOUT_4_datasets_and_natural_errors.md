## 0. Headline findings

1. **Closest prior art, and a ready test set: Ma et al., arXiv 2610.18497** ("Judges Follow the Reference: The Derivation Gap in Verifying Tool-Call Arguments", Oct 2026). Seven judges (CLM, Jev, Qwen3, Mistral, Llama) verify argument values; they accept correct values less often when the input holds no textual reference for them (defaults, inferred values, truncated returns). Data: HF `lm2445/DeRef` (Apache-2.0, open, modified 2026-10-15). Code: `github.com/SarielMa/DeRef_release` (Apache-2.0, pushed 2026-10-14; "No model outputs or results are included"). The paper said release would come "after review"; it is already public. Reviewers will ask for a comparison with it. It is also the best single N1 source (section 3, R1).
2. **BFCL does publish PER-MODEL raw outputs with scores and error labels, but not in the main repo.** `github.com/HuanzhiMao/BFCL-Result` (Apache-2.0; README: "hosts all model responses used to generate the BFCL leaderboard, together with their evaluation scores"; 3.1 GB repo, 22 dated release folders). Release `2025-12-16` (BFCL v4) has 109 model folders, `2025-04-25` has 120 (result) / 121 (score), `2024-11-13` has 70. Per model: `result/<model>/{agentic,live,multi_turn,non_live}/BFCL_v4_<cat>_result.json` and `score/<model>/.../BFCL_v4_<cat>_score.json`. The gorilla main repo has no `result/` or `score/` (the commits API returns nothing for those paths); its README says you create them by running models. Mirrors: HF `AgentSuite/BFCL-trajectories` (26 models x 4,441 tasks) and `AgentSuite/BFCL_V4-trajectories`; `ibm-research/fc-reward-bench` (1,500 correct/rejected pairs built from the BFCL team's model generations).
3. **Hallucinated-Tools Benchmark (arXiv 2609.19425, Iyer, "Independent Researcher"): I found NO download location.** Evidence: the abs page has no comments, journal ref or code link; the HTML and PDF contain no URL; the only pointer is the sentence "pip install toolguard; toolguard-bench". PyPI `toolguard` 0.2.21 exists but is a different project (IBM Research, authors @il.ibm.com, "Towards Enforcing Company Policy Adherence in Agentic Workflows", arXiv 2507.16459); `toolguard-bench` and `hallucinated-tools-benchmark` are 404 on PyPI; 3 GitHub repo searches found only unrelated `dondetir/toolguard-benchmark` (TMLR paper on red-teaming small models) and `Mohin271/ToolGuardBench-Benchmark`; HF searches `htb`, `toolguard`, `hallucinated-tools` found nothing relevant; Zenodo search was blocked (HTTP 403, not checked). The paper also says a held-out split is "not shipped". It is registry-level (tool existence, schema, MCP namespace collisions), only its H5 class ("borrowed signature", schema-valid arguments) touches arguments. Verdict SKIP; the author email printed in the PDF is iyer.la@northeastern.edu if the team wants it.
4. **Ceiling warning from D1 (my own count over the released files).** In DeRef `fcrb`, of 769 wrong arguments only 418 (54%) have path `no_source` (value absent from context, the thing our checker targets); 258 (34%) are `visible` (value present but wrong choice/format). Conversely 533 of the correct arguments are `no_source` (inferred/defaults), so "unsupported" is wrong in only 418/(418+533) = 44% of cases. In `cfb`: wrong = 747 no_source, 181 visible, 59 history_only, 12 format; correct no_source = 462, so precision of "unsupported => wrong" is 747/(747+462) = 62%. Any grounding checker, ours included, inherits this derivation gap. Path labels are the authors' own automatic labels, so treat them as approximate.
5. **Label caution for BFCL.** The BFCL checker label "wrong" means "differs from gold", not "ungrounded". Example read from the gpt-4.1 live_simple score file: model wrote `location: "上海, 中国"` copied from the user's Chinese text, marked wrong only because gold wanted "Shanghai, China". In `ToolRM-train-data` I saw `"EUR"` vs gold `"eur"` counted as incorrect. N1 needs an adjudication pass (section 4).
6. **Injection data with real model-made structured calls exists:** AgentDojo `runs/` (MIT). I verified `security=true` means the injected call was executed (the example run has a `send_email` to the attacker address with the injected body and `security: true, utility: false`).

## 3. Extraction recipes (schemas inspected)

Run Python with `-I` on downloaded files; keep downloads in their own folders.

**R1. DeRef (`lm2445/DeRef`)** - best first step.
```
curl -L -o fcrb.jsonl https://huggingface.co/datasets/lm2445/DeRef/resolve/main/data/fcrb.jsonl   # 3.7 MB
curl -L -o cfb.jsonl  https://huggingface.co/datasets/lm2445/DeRef/resolve/main/data/cfb.jsonl    # 28.5 MB
# fintrace.jsonl ~131 MB: page it via datasets-server /rows?dataset=lm2445/DeRef&config=fintrace&split=test
```
Fields (all configs): `dataset,item_id,query_id,state_id,call_label,request,history,plain_window,plain_rung,action,action_with_description,calls,functions,arguments,source_meta`.
Mapping: context = `request` + `history` (cfb: list of `{label,kind:"call"|"return",step,name,text}`, long JSON returns; fcrb: empty); planned call = `calls[i]` (`{call_index,name,arguments}`) or the string `action`; call label = `call_label` (correct/wrong); argument labels = `arguments[j]` with `name,value,label,path,in_analysis` (use only `in_analysis==true`). Paths: fcrb `visible,no_source,default,format,placeholder`; cfb `visible,history_only,no_source,format`. cfb `source_meta` = `{task_id,k,models,official_accepted}`; fintrace `source_meta` = `{turn,call_idx,endpoint,p4_subtype,p4_change}` (single-argument rule change, e.g. `{"symbol":["XOM","HAL"]}`).
Counts I computed: fcrb 630 correct + 630 wrong calls, 3,574 arguments (2,488 in analysis; 769 wrong); cfb 347 correct + 644 wrong calls over 299 queries, 4,673 arguments (2,638 in analysis; 999 wrong), median history 4 steps, max 14, 29 distinct source models listed.
Caveats from the paper: cfb/fintrace wrong labels are the authors' own construction (two annotators could not confirm 3% and 4% of 100 audited items); fcrb labels follow the official BFCL checker, unaudited.

**R2. BFCL-Result (per-model raw outputs + scores).**
```
B=https://raw.githubusercontent.com/HuanzhiMao/BFCL-Result/main/2025-12-16
M=gpt-4.1-2025-04-14-FC
curl -L $B/score/$M/live/BFCL_v4_live_simple_score.json     # 167 KB
curl -L $B/result/$M/live/BFCL_v4_live_simple_result.json   # 74 KB
```
Both files are JSON Lines. Score file: line 1 = `{"accuracy":0.6938,"correct_count":179,"total_count":258}`, then ONE LINE PER FAILING ITEM with keys `id,model_name,test_category,valid,error[],error_type,prompt{id,question[[{role,content}]],function[schema]},model_result_raw,model_result_decoded,possible_answer`. Result file: every item, `{id,result:[{fn:"<json string>"}],input_token_count,output_token_count,latency}`.
Mapping: context = `prompt.question` turns (+ schema `prompt.function`); call = `model_result_decoded` (`[{fn:{arg:value}}]`); label = failing (score file) with `error_type`; passing = ids in result file but not in score file (fetch the prompt and gold from `bfcl_eval/data/BFCL_v4_<cat>.json` and `possible_answer/` in ShishirPatil/gorilla). gpt-4.1 live_simple: 79 failures of 258; `error_type` counts: value_error:string 36, ast_decoder:decoder_failed 12, value_error:others 9, value_error:dict_key 7, simple_function_checker:wrong_count 4, value_error:list/tuple 4, value_error:dict_value 3, type_error:simple 2, type_error:nested 1, missing_required 1. Keep `value_error:*`/`type_error:*` for argument-level work; drop decoder/count/name errors.
Multi-turn (`multi_turn_base`, gpt-4.1: accuracy 0.475, 95/200): failures carry `error.error_type` `multi_turn:instance_state_mismatch` with `details.execution_result` (per-step tool outputs, e.g. `{"error": "mv: cannot move 'final_report.pdf': No such file or directory"}`) and `inference_log`. The label is END-STATE, not per call: derive per-call labels from environment error outputs or relabel.

**R3. AgentSuite BFCL** (`AgentSuite/BFCL-trajectories`). One file per model, e.g. `.../resolve/main/DeepSeek-V3-0324.jsonl` (35-52 MB each). Rows: `model_path,user_model_path,benchmark_name,task_name,sampling_params,user_sampling_params,messages,eval_result{score},meta{id,task_type,valid,error,error_type,result,model_result_raw,model_result_decoded,possible_answer,input_token_count,output_token_count,latency,inference_log}`. 17 `task_name` values (live_multiple 27,378 rows, live_simple 6,708, multi_turn_* 5,200 each, etc.); rows are NOT grouped by category (offset 700 = multi_turn_base_42, offset 250 = multi_turn_long_context_50). Single-turn: `messages[0]` = user text + "Available functions" list, `messages[1]` = bracket-syntax call, `meta.result` = structured call, `meta.error` = checker message. Multi-turn: `messages` is lossy; the full conversation with tool outputs is in `meta.inference_log` (a list: `state_info`, then a dict `begin_of_turn_query`, `step_0`, `step_1`... each holding the assistant call, handler log, and `{"role":"tool","content":...}`). Label = `meta.valid` / `eval_result.score` / `meta.error_type` (same BFCL caveat). Use datasets-server `/rows` (100 per request; `/filter` timed out with 500 "index is loading" on this 1.3 GB set) or one model file via HTTP.

**R4. AgentSuite tau-bench / tau2 / CFB.** Row keys as above. tau-bench row: `messages` = `[{role:system|user|assistant|tool, content, turn_idx, tool_calls:[{function:{name,arguments:"<json str>"},id,type}]}]`; `eval_result={score,db_match}`; `meta.task_description.actions` = gold write actions `[{name,kwargs}]`, `meta.task_description.instruction`, `meta.id` (`airline_0`). CFB row: roles `user`, `assistant` (`tool_calls:[{name,arguments:{...}}]`), `observation` (`content`: list of long JSON returns); `meta.count_dict={success_turn_num,total_turn_num,correct_call_num,total_call_num,real_turn_num}`. Labelling a tau-bench write call: exact-match `(name, kwargs)` against `meta.task_description.actions`; mismatch => "differs from gold" (not necessarily wrong). Read-only calls have no gold; environment strings starting with `Error` are a weak automatic label (73 of 1,164 tool outputs in the gpt-4o airline file, all from `update_reservation_flights` 42, `book_reservation` 30, `update_reservation_baggages` 1; e.g. "flight HAT030 not available on date 2024-05-13").

**R9. Hermes.** Configs `func_calling_singleturn`, `func_calling`, `glaive_func_calling` (+ `json_mode_*`): `id,conversations[{from:system|human|gpt|tool,value}],tools,category,subcategory,task`. Calls: `<tool_call>\n{"name":...,"arguments":{...}}\n</tool_call>` (several per turn); outputs `<tool_response>\n{"name":...,"content":{...}}\n</tool_response>`. I opened singleturn and glaive; I did not open `func_calling` (multi-turn) rows.

**R10. MCP-Atlas.** Parquet columns `TASK,ENABLED_TOOLS,PROMPT,GTFA_CLAIMS,TRAJECTORY`; `TRAJECTORY` is a JSON string: assistant `tool_calls[].function{name,arguments:"<json str>"}` and tool messages with `content:[{text,type}]` holding real MCP server output (e.g. GitHub search results). Arguments of call k+1 are frequently copied from the output of call k, ideal for provenance tests.

## 4. Proposal: natural-error set N1 without running any model

Principle: reuse model outputs that already exist, relabel with a grounding-aware protocol, keep four strata.

- **N1-single (about 4k-12k labelled calls, depends on how many models are pulled).** (a) `fc-reward-bench`: 1,500 correct + 1,500 rejected, of which 650 "parameter value error" (published table). (b) BFCL-Result 2025-12-16: pick 25-30 diverse models (open and closed, 0.5B-frontier), `live_simple + live_multiple + live_parallel + live_parallel_multiple` (258 + 1,053 + 16 + 24 prompts). From one measured model (gpt-4.1: 79/258 failures on live_simple, 59 of them value or type errors) I extrapolate a few hundred failures per model, i.e. on the order of 10k before dedup on (id, wrong value) - this is an extrapolation, not a count.
- **N1-multi (context with tool returns).** (a) DeRef `cfb`: 644 wrong + 347 correct calls with real long returns (already filtered, per-argument paths). (b) tau-bench/tau2 via AgentSuite: 30 models x 165 (tau) and 278 (tau2) tasks; label write calls against gold; gpt-4o airline averages about 5.8 tool calls per trajectory. (c) tau-bench GitHub trajectories (gpt-4o, sonnet-35-new) as a clean-licence subset (MIT).
- **N1-human.** AgentHallu BFCL subset: 36 human-labelled "Incorrect Tool Arguments" trajectories + 61 clean (use as the audited gold; tiny).
- **N1-inject.** AgentDojo runs: executed injection calls (`security==true`) vs the same agent's benign calls.

Label protocol (so "wrong != ungrounded" does not contaminate): for every mismatched argument assign one of {ungrounded-wrong (value absent from all admissible sources), grounded-but-wrong (present but wrong choice, DeRef `visible`), format-equivalent (case, units, language), acceptable-alternative}. Step 1 automatic: normalised string/number containment over context + tool returns + schema defaults/enums (this IS our checker's logic, so also add an independent LLM adjudicator to avoid circularity). Step 2: two human annotators on a stratified 200-item sample (Ma et al. audited 100 per dataset and report 3-4% unconfirmed). Report both "gold-mismatch" and "adjudicated" labels, and report results per DeRef path (visible / history_only / no_source / default / format).

Free external baselines: the DeRef repo already scripts CLM, Qwen3, Llama, Mistral and Jev judges (GPU needed for local ones; Jev via OpenRouter key; CLM weights `CLM_v0.1-8B.pt` per its README).

## 6. Gaps and cautions

- No public multi-turn dataset has HUMAN per-call argument labels at scale; the only human set found is AgentHallu BFCL (36 argument cases). DeRef labels for cfb/fintrace are author-constructed.
- BFCL multi-turn labels are end-state; tau-bench labels are trajectory-level plus gold write actions only; MCP datasets (MCPMark, MCP-Atlas) have task-level success or gold only. Per-call labels for real MCP servers do not exist publicly.
- Hallucinated-Tools Benchmark unobtainable (section 0.3). SAAG and ToolHACE data not found. ToolBench/StableToolBench, RobustBench-TC and ToolBeHonest were not inspected.
- `AgentSuite/*` datasets declare no licence and I did not identify the owner; cite the upstream benchmark licences (BFCL Apache-2.0, tau-bench MIT, ComplexFuncBench Apache-2.0 per the DeRef paper) and prefer GitHub sources (R2, R5) for publishable results.
- InjecAgent has no model-made attacker calls; ASB is a framework; the HF AgentDojo flat copy has undocumented `label`.
- I did not run any model or judge, and did not download datasets larger than about 30 MB. Counts marked "extrapolation" are not measurements. DeRef path labels are the authors' automatic labels.
- The 2026-10-16 to 2026-10-20 HF datasets-server was intermittently rate limited (429/500/502/503); `/filter` on the 1.3 GB BFCL trajectories failed with "index is loading".

## 7. Ten-line summary

1. Most important find: Ma et al. 2610.18497 (judges verifying tool-call arguments) is direct prior art; data `lm2445/DeRef` (Apache-2.0) and code `SarielMa/DeRef_release` are public.
2. DeRef gives per-argument correct/wrong labels with derivation paths on natural errors: fcrb 1,260 calls, cfb 991 calls with real tool returns, fintrace 4,668 (rule-made).
3. BFCL per-model raw outputs and scores exist in `HuanzhiMao/BFCL-Result` (109 models in 2025-12-16, 22 releases, Apache-2.0); failing items live in score files, passing in result files.
4. HF `AgentSuite/*-trajectories` give 26-30 models on BFCL, tau-bench, tau2, ComplexFuncBench (no licence declared); tau-bench GitHub historical trajectories are MIT.
5. Hallucinated-Tools Benchmark (2609.19425): no download location exists that I could find; `pip install toolguard` is an unrelated IBM package; SKIP.
6. Human-labelled natural argument errors are scarce: AgentHallu BFCL subset has 36 "Incorrect Tool Arguments" (+61 clean trajectories).
7. Ceiling warning: in DeRef fcrb only 54% of wrong arguments are absent from context and 44% of unsupported values are actually wrong (62% in cfb); report results per derivation path.
8. BFCL "wrong" often means "differs from gold" (e.g. a Chinese place name copied from the user): relabel before treating as ungrounded.
9. Injection tests: AgentDojo `runs/` (MIT) has real executed injections with structured calls; `security=true` verified as attacker success.
