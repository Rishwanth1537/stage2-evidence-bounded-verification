## 3. What our split-conformal threshold does and does not guarantee

**Rule** (`server/pipeline/arg_ground.py: conformal_threshold`): n genuine calibration scores; `k = floor(alpha (n+1))`; `tau = S_(k)` (0 if `k < 1`); block iff `S < tau`. The benchmark has 1,704 premises, 1,828 genuine calls and 1,676 injected errors, so each dev/test half has n of about 914-920 genuine calls (dev `n` = 1753 cases; confirm).

**Theorem (finite sample, distribution-free).** If the scores of the n calibration genuine calls and of a new genuine call are exchangeable, and the scoring function and every constant (e.g. `FUZZY = 0.88`) were fixed before seeing calibration scores, then
`P(S_{n+1} < S_(k)) <= k/(n+1) <= alpha`, with equality `k/(n+1)` for continuous scores.
Proof sketch: if `S_{n+1} < S_(k)` strictly, its rank among the n+1 scores is at most k under any tie-breaking; ranks are uniform under exchangeability. This equals CRC Thm 1 with `B = 1` and 0/1 loss: the rule `(sum_i 1{S_i < tau} + 1)/(n+1) <= alpha` picks the same `tau`. Ties (many genuine calls at exactly 1.0 or 0.0) make the strict rule conservative; a non-strict rule `S <= tau` would be unsafe with ties.

**What "false-block rate" means.** `P(block | genuine call)`: a one-class (Mondrian-by-label) guarantee computed from genuine calls alone (#1). It needs no error examples and says nothing about errors.

**What it does NOT give.**
1. *Not conditional on your calibration set.* The probability averages over the calibration draw and the new call. For one fixed calibration set the realised rate is `Beta(k, n+1-k)` (continuous scores; #1, #2, #3). For n = 920 (my computation): alpha = 2%: mean 1.95%, SD 0.46 points, `P(realised > alpha) = 0.43`; alpha = 5%: mean 4.99%, SD 0.72, `P(> alpha) = 0.48`, `P(> 6%) = 0.086`; alpha = 10%: SD 0.99. About half of calibration draws exceed alpha. Your 3.7% (budget 5%) and 7.3% (budget 10%) are below budget because score ties make the strict rule conservative and by chance; they are not evidence of a better-than-guaranteed method.
2. *Not "with 90% confidence the rate is <= alpha".* For that use the calibration-conditional rule (#1 Thm 4, #5, #6): the largest `k'` with `P(Bin(n, alpha) <= k'-1) <= delta` (continuous scores). n = 920, delta = 0.1: `k'` = 13 / 38 / 80 instead of 18 / 46 / 92 for alpha = 2% / 5% / 10%.
3. *Not a precision guarantee.* With error prevalence pi, the share of blocks that are genuine is `(1-pi) FBR / ((1-pi) FBR + pi TPR)`. At FBR 5%, TPR 87.5%: 5% of blocks wrong at pi = 50% (about your test mix), 34% at pi = 10%, 85% at pi = 1%. Report the sweep (#15 Sec 4.6 does the same for email).
4. *Not valid under dependence between calls.* In D1 the risk is small: 95% of premises have exactly one genuine call (mean 1.07), so effective n is close to nominal. For D2-D4 (especially multi-turn) measure calls per conversation first. If large, calibrate with one random call per conversation (finite-sample valid for a new call from a new conversation, #7 Thm 5; for our one-sided rule I expect the analogous requirement `k_conv >= 1/alpha - 1` conversations, my adaptation) or accept the factor-2 loss of repeated subsampling (#7 Thm 6).
5. *Not valid under shift.* If calibration scores are i.i.d. from P and the new genuine call is from Q, then `P_Q(block) <= alpha + TV(P,Q)` (my one-line derivation: the joint law differs from the exchangeable one in a single coordinate; Prop 4 of #16 states the fixed-threshold version; #4 Prop 3 and #8 give looser general forms with a sum or factor 2). TV is not estimable; the KS distance between source and target genuine-score distributions lower-bounds it. Class-conditional guarantees can fail badly under shift even when marginal coverage looks fine (#17a).
6. *Not a detection guarantee.* 87.5% and 97.8% are empirical and depend on how realistic the injected errors are (bool-flip detection is 0.0 in the result file).
7. *Infeasibility is a theorem.* If `alpha < 1/(n+1)` then `k = 0`; if more than alpha of genuine calls score exactly 0 then `tau = 0` and nothing is blocked (#16 states the floor `1/(n+1)`; #6 the sample-size requirement). At alpha = 2% the file shows `tau = 0`, so at least about 18 of ~920 genuine dev calls score exactly 0; the bench metadata says 93.5% of gold values appear in the premise (about 6.5% do not). A deterministic stage cannot go below that floor without blocking those calls; a judge stage can, which is the cascade argument.
8. *Label contamination and selection.* If some calibration "genuine" calls are really errors, and errors score lower than genuine calls (stochastic dominance), the contaminated CDF lies above the clean one, `tau` moves down, and the rate on truly genuine calls stays `<= alpha` (my one-line argument; consistent with the "conservative under dispersive noise" abstract of #10). The dangerous direction is different: gold calls copied from context are easier than the correct-but-reformatted calls of a real agent, so `tau` can be too high on deployment traffic. That is an exchangeability failure, which the natural-error set N1 can expose.

**Recommended practice.** (a) Keep the marginal rule; state it as "marginal over calibration draws, under exchangeability of genuine calls" and cite #2, #1 Prop 1, #4 Thm 1. (b) For a headline "guarantee" use the calibration-conditional rule (#1 Thm 4 / binomial order statistic, with #5 for several thresholds). (c) Report the re-split check of #2 Sec 3.3 (draw 1,000+ random splits; count how often realised FBR `<= alpha`). (d) Cascade thresholds by Learn-then-Test (#5), as #11 does for judges. (e) Per-risk-tier budgets by Mondrian strata with the floor `1/(n_s+1)` and pooling (#16). (f) For shift: weighted conformal (#9) or a small target recalibration set, else quantify with KS and report as empirical.

## 4. Cascades with verifiers: what is known (numbers only where read)

- **Trust or Escalate (#11, FT).** Judge confidence from 5 simulated annotators (ECE down about 50% and AUROC up 13% for GPT-4 versus baselines, per the paper); thresholds by fixed-sequence testing with exact binomial upper bounds; guarantee with probability `>= 1-delta` over the calibration set, contrasted with methods centred at alpha on average. Calibration set 500 (ChatArena), 392 (Auto-J). ChatArena: 91% guarantee success rate; GPT-4 used on only 17.5% of evaluations; coverage 79.1%, of which 88.1% done by Mistral-7B or GPT-3.5 (both figures as stated in the paper, in different sections and possibly different settings). Where GPT-4 alone almost never reaches 80% human agreement, the cascade guarantees over 80% at almost 80% coverage. It abstains on the rest, and the guarantee is on agreement of accepted verdicts, not on a clean-class false-positive rate.
- **FrugalGPT (#12, FT).** Cost to match the best single model falls 98.3% / 73.3% / 59.2% on three tasks (Table 3); the paper's maximum-performance-improvement measure shows cheaper models could add up to 6% on HEADLINES over GPT-4 (an upper bound), which is the diversity a cascade exploits and the reason to test error independence (H5).
- **Conformal Cascade (#13, IN).** Tier-wise guarantees compose to `1 - K alpha` only; use end-to-end calibration.
- **Cheap Verifiers (#14, IN).** Verifier blind spot grew from 0.12 to 0.55 as the student grew from 0.5B to 32B; a frontier verifier lowered it to about 0.05 but then escalated 46% of hard-MATH queries against a 39% true error rate; the cascade's own dashboard read about 3% error while true delivered error reached 32%. Lesson: report errors the first stage lets through, measured with an independent reference.
- **ConformalGuard (#15, FT).** At a 1% legitimate-class FPR target: Claude Sonnet 4 recall 0.938 -> 0.875 (FPR 4.0% -> 0.8%); deterministic GPT-4o recall 0.887 -> 0.564 (FPR 0.1%) because its scores take 10 values; averaging three samples (105 distinct values) gives recall 0.732 at FPR 0.51%. Cross-source shift: BERT calibrated on Enron ham reached FPR 2.1% on SpamAssassin ham at a 1% target.
- **Abstract-only cost claims, treat as unverified:** Hybrid LLM up to 40% fewer large-model calls; RouteLLM over 2x cost reduction; RouteNLP (2604.23577) 58% cost cut in an 8-week pilot; UCCI (2605.18796) 31% cost cut at micro-F1 0.91 on NER.
- **Deterministic gates (2607.07405, AB).** Four deterministic pre-execution gates raised tau2-bench airline success from 29.6% to 42.0% on gpt-4o-mini (paired task-level bootstrap). Supports the value of a deterministic first stage; not a cascade.
- **Judge scores are coarse:** verbalised scores have few values (#15), k votes give k+1 values, log-probabilities may not be exposed by hosted APIs (check Groq/NVIDIA).

## 5. Analysis plan

Data facts: about 838 error cases and 914 genuine calls per half; about 0.98 errors and 1.07 genuine calls per premise, so clustering by premise is mild in D1 (use it anyway; measure for D2-D4).

### H1 non-inferiority at matched FBR
- **Estimand.** `Delta = TPR_S2(alpha) - TPR_J(alpha)`: each system's threshold set by the same rule on the same dev genuine calls at the same alpha, so each has marginal FBR `<= alpha` by construction; TPR on the test-half errors. Report realised test FBR for both; if they differ by more than 1 point add a ROC-interpolated comparison.
- **Test.** H0: `Delta <= -0.02` vs H1: `Delta > -0.02`, one-sided 5%. Primary: premise-cluster bootstrap (at least 10,000 resamples), reject if the 5th percentile of `Delta*` exceeds -0.02, with the two-layer scheme: resample dev premises, recalibrate both systems, then resample test premises (calibration noise has SD about 0.7 points in FBR at alpha = 5%, Sec 3). Sensitivity: studentised/BCa bootstrap and a Tango-type score interval for paired proportions (Tango 1998; Liu, Hsueh, Hsieh; Saeki and Tango 2011/2016 for clustered matched pairs; MD only). Near 0.9-1.0 detection, Wald and plain percentile intervals undercover (Anglin, AB), so Wilson/Clopper-Pearson for single proportions. McNemar (1947) tests equality, not a margin: use it for the discordant-pair table only.
- **Power (my arithmetic, n_err = 838, no cluster inflation).** SE of `Delta_hat` is about `sqrt(q/n)` for discordance rate q. One-sided 5% bound: 0.98 / 1.27 / 1.80 points for q = 3% / 5% / 10%, so with margin 2 points `Delta_hat` must exceed -1.0 / -0.7 / -0.2 points; with margin 1 point it must exceed 0.0 / +0.3 / +0.8. Errors needed for 80% power at true `Delta = 0`: `6.19 q / m^2` = 464 / 773 / 1,546 for m = 2 points, and 4x that for m = 1 point (3,093 at q = 5%). Compute the real q before choosing the margin: a 2-point margin is powered at 80% only if q is at most about 5%, and a 1-point margin is unpowered with this benchmark.
- **Several judges.** Non-inferiority to every judge is an intersection-union test (each at 5%, no adjustment inside H1). "Best judge" must be fixed on dev. Holm across H1-H6 as pre-registered.
- **Judge operating points.** Use a continuous or ordinal confidence (log-prob where available, else vote share/verbal). With ties, add randomised tie-breaking for the matched-FBR arm and also report the deterministic one.
- **Prevalence.** Report precision and false-discovery share at pi in {1, 5, 20, 50%} (Sec 3 item 3).

### H2 cascade cost
- **Design.** Choose `(tau_low, tau_high, judge cut)` by Learn-then-Test on dev genuine calls with the end-to-end cascade false-block event as the risk (#5; fixed-sequence ordering from cheapest to costliest, or Bonferroni over a grid). Any certified member is valid, so pick the cheapest on dev; estimate its cost on the test half.
- **Estimands.** Escalation share on genuine (`e_g`) and error (`e_err`) calls separately; `e(pi) = (1-pi) e_g + pi e_err`. "<= 20% escalated" has no meaning without pi. Cost per call `c_S2 + e c_J` from measured tokens and latency.
- **Tests.** Escalation: one-sided cluster-bootstrap upper bound below 0.20. Accuracy: non-inferiority of cascade vs LLM-only detection at matched FBR (as H1; margin 1 point is unpowered, see above, so state the margin you can actually power). Latency: if `e > 5%` the cascade p95 is the `(1 - 0.05/e)` quantile of the judge's latency plus S2 time (the judge's 75th percentile at e = 20%), so p95 gains are far smaller than p50 gains; if `e < 5%` p95 is the S2-only latency.
- **Cross-check.** Union bound without independence: `FBR_cascade <= alpha_1 + alpha_J` when stage 1 and the judge are each calibrated on all genuine calls; joint calibration is tighter.
- **Leakage (from #14).** Count errors S2 allows without escalation and how many of them the judge would have flagged.

### H6 coverage under dataset shift
- **Fix the decision rule.** "FBR <= budget on >= 3 of 4 sets" fails about half the time with no shift, since `P(realised > alpha) = 0.43-0.48` (Sec 3). Under exchangeability the number of false blocks among m target genuine calls is beta-binomial `(m, k, n+1-k)` (continuous scores; conservative with ties). Report the upper-tail p-value per dataset, inflated by a cluster design effect, and flag datasets with small p. Primary budget: 5% only; others descriptive.
- **Per dataset and budget:** observed FBR with premise-cluster CI; excess over alpha; KS distance between source and target genuine-call scores; FBR after (i) recalibration on 100 / 200 / 500 target genuine calls, (ii) weighted conformal with a density ratio estimated from call features (#9), (iii) pooled multi-source calibration.
- **Expect** class-conditional tails to fail under shift (#17a) and recommend target-side recalibration.

## Summary (10 lines)
1. Our threshold is the B=1 conformal-risk-control / one-class conformal rule; it gives `P(block | genuine) <= alpha` on average over calibration draws, under exchangeability, with strict "<" safe under ties.
2. For one calibration set the realised rate is Beta(k, n+1-k): SD 0.7 points at alpha 5%, n 920; about half of draws exceed alpha. Use the binomial order-statistic rule for "with 90% confidence".
3. Not guaranteed: precision (85% of blocks wrong at 1% error prevalence), detection, shift (bound `alpha + TV`), label contamination in the other direction, and alpha below the 1/(n+1) and score-zero floors.
4. Closest prior art: ConformalGuard 2610.14365 (email, no cascade), role-stratified CRC 2607.24343 (injection, per role), Trust or Escalate 2407.18370 (judge cascade, agreement guarantee). I found none doing deterministic-first cascades with an FBR guarantee.
5. Cascade evidence: Trust or Escalate used GPT-4 on 17.5% of cases at 79.1% coverage; FrugalGPT saved 59-98%; Cheap Verifiers shows hidden blind spots (dashboard 3% vs true 32%).
6. H1: premise-cluster bootstrap with recalibration inside, margin test on Delta; with 838 errors a 2-point margin is powered only if the two systems disagree on at most about 5% of errors; a 1-point margin is not.
7. H2: Learn-then-Test over cascade thresholds, escalation reported per class and per prevalence; above 5% escalation the cascade p95 is set by the judge's latency tail.
8. H6: replace "FBR <= budget" with a beta-binomial exchangeability null, KS shift diagnostic, and recalibration/weighting repairs.
9. Eight add-ons, strongest: certified cost-aware cascade, conformalised judge scores for matched FBR, risk-tiered Mondrian budgets, leave-one-dataset-out shift study.
