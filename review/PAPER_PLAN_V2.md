# Paper plan v2 (2026-10-30): evidence-bounded verification of tool-call arguments, and asking instead of blocking

Status: scope decision taken by the user (stances 1 + 2 combined, scoped to be competitive for a main-track venue). This file supersedes `NOVEL_PROJECT_PLAN.md` for the paper; that file stays as history. Numbers come from `EXPERIMENTS_2026-10-30.md` and are development-half results only.

## 1. Thesis (one sentence a reviewer can disagree with)
**Verifying a tool-call argument is limited by the evidence the verifier can see, not by the verifier's size; a verifier can only decide the errors that its evidence decides, and for the rest the right action is to ask the user, with disagreement between models as the trigger and a distribution-free budget on how often it interrupts.**

## 4. Hypotheses to register before any test run
(Detailed wording in `PREREGISTRATION.md`, Deviation 12.)
- **H-I1 (information).** For each judge, detection with E2 evidence exceeds detection with E1 evidence by at least 10 points at an equal-or-lower false-block rate; the slope with model size inside a condition is below one third of that gain.
- **H-I2 (decidability bound).** Judge detection (E1) is within 10 points of the share of errors labelled E1-decidable plus the false-block rate.
- **H-A1 (ask value).** At an interruption budget alpha = 10% of correct calls, an ask-policy using peer disagreement plus contract violation catches at least 15 points more wrong calls than a policy using the contract violation alone.
- **H-A2 (guarantee).** Across 1,000 random calibration/test splits by conversation, the realised ask-rate on correct calls stays at or below alpha in at least 90% of splits when alpha is calibrated with the finite-sample conformal rule (and the miss rate is reported when it is not).
- **H-A3 (shift).** Calibrating on BFCL and testing on tau-bench or DeRef, the realised ask-rate exceeds alpha; report by how much and test the three repairs (recalibrate on 100/200/500 target calls, weighted conformal, pooled calibration).

Kill rules: if H-I1 fails on the locked test, the paper becomes a negative-results/measurement note; if H-A1 fails, drop C3 as a headline and keep C1, C2, C4, C5.

## 8. First ask-policy results (dev, 2026-10-30) and what they change
- Peer disagreement is a strong ask-trigger on BFCL (call-level AUROC 0.891); the contract flag is weak alone (0.572) and does not improve it when added (0.877). H-A1 as written (consensus plus contract vs contract alone) holds trivially; the interesting comparison is consensus vs a schema-aware judge, which was not significant (production of a better control is a priority).
- The guarantee needs care. Plain split conformal keeps the mean interruption rate at its target but is within target in only 57 to 62% of calibration draws. Because the 30 models answer the same test cases, calls inside a case are near-duplicates; treating the test case as the unit and bootstrapping cases gives >99% of splits within target, but detection falls from 49 / 65 / 85% to 14 / 33 / 61% at alpha 0.05 / 0.10 / 0.20 with about 100 calibration cases. So a real result for C3 is the price of a calibration-conditional guarantee as a function of the number of calibration cases (to be plotted by subsampling and by adding tau-bench and DeRef cases).
- Pre-registration H-A2 was reworded (Amendment 12b) before any test run.
- A fair main-track version needs the ask-policy evaluated with real agent self-consistency (k samples from one model) and not only 29 other models, since the deployed cost of peer disagreement is the central practical objection.

## 9. Decidability labels and the audit (2026-10-31)
- `benchmarks/decidability.py` assigns each wrong argument to the weakest evidence source that decides it (rules in its header; no verifier verdict is used). ## 12. Rule revision after the pre-audit, and BFCL recomputed on strong errors (2026-11-01)
**Protocol.** After seeing the Opus pre-audit (section 11) the decidability rules were revised using ONLY audit items A001-A050 (tuning half); A051-A100 were kept as a held-out check. The human audit still covers all 100 items, but its first half is no longer independent of the revised rules; report it that way.
**Changes** (`benchmarks/decidability.py`, `benchmarks/contract_tier.py` with `relaxed=True`): (i) two WEAK label tiers for BFCL "wrong" arguments: `WEAK_format_variant` (the value is a format variant of a gold alternative or equals the tool's default: case/punctuation, one string containing the other, equal numbers, equal dates/times in different forms) and `WEAK_optional_unrequested` (gold leaves the optional argument blank); (ii) E1 requires that the conversation states the right value AND does not support the agent's value; a value the conversation supports but the tool definition rules out is E2; (iii) contract format checks accept a time after an ISO date, 12-hour times and array-item enums; (iv) fcrb: an agent that used `dontcare`/default although the conversation states a value, and an unsupported number when the conversation contains numbers, are E1.
**Held-out result (A051-A100, Opus as annotator):** the WEAK tiers generalise (annotator calls 0 of 11 weak items wrong; all 100 items: 3 of 26), BFCL label precision of the remaining strong items about 56% on the held-out half (25% on all of its items); but class agreement on the held-out half did not improve (9/18 before and after; 24/38 over all 100 under the new rules, 20/41 under the old). The peer class E4 cannot be validated by a human question (annotators answered "only the user" in 4/4) and is reported as unaudited. The "silent" class (unsupported values) draws "conversation" from the annotator in about 3/4 of cases, so it overlaps E1 and should be read as "unsupported".
**New counts (all development data, rule-based):** BFCL 819 wrong arguments = 43.6% format variants + 19.2% optional-unrequested (WEAK, 62.8%) + silent 12.2% + user choice 8.2% + contract 7.0% + conversation 5.6% + peers 4.3%; only about 37% are strong errors. fcrb dev (388): silent 42.8%, conversation 39.9%, contract 17.3%. tau-bench (737 suspect): user choice 86.6%, state 13.4%.
**BFCL recomputed on strong errors** (calls whose only errors are weak labels are dropped; `--strong` in `ask_policy.py` and `compare_consensus_judge.py`):
- Judge control, Opus with the tool definition, 858 calls (43 wrong): judge 8.0% false blocks / **65.1%** detection (45.9% on all labels); consensus at the same rate 74.4%; union 88.4%; consensus minus judge 95% CI -0.19 to +0.40 (not significant; 43 wrong calls).
- Ask-policy, 4,996 calls (255 strong-wrong): consensus AUROC 0.892 (unchanged); **the contract flag falls to AUROC 0.516** (flags 4.6% of correct and 7.8% of wrong calls): its apparent value on BFCL came from the weak-label format artefacts. Plain conformal caught 64% / 81% / 85% of strong errors at budgets 5 / 10 / 20% (65% / 85% on all labels at 10% / 20%...); the cluster-bootstrap rule caught 20% / 42% / 78% with >=99% of splits within budget.
**Consequences.** Every earlier BFCL number was computed on unfiltered labels and is superseded by the strong-error versions above (consensus findings, contract tier on BFCL, judge control, ask-policy); the fcrb information-ablation numbers use fcrb labels (pre-audit precision 67%, no reference values to filter with) and keep their caveat. **Registered outcomes.** H-J1 (a judge detects more than the checker at a false-block rate not above the checker's, Holm-corrected over five judges): **not supported for any of the five judges**; the checker has the highest detection and the highest J. The nominally clearest difference is Nemotron 4B (9 vs 23 discordant cases, p = 0.020, Holm 0.10, in the checker's favour). H-J2 (judge detection below 70%): **supported for all five** (32-48%).
**Reading and limits.** Only 31 positives: intervals are wide (most judge-vs-checker differences are not significant), so this is evidence that the checker is competitive on this error type, not that it is better. The two results together support the thesis that which verifier works depends on the error type and on the information the verifier has. The checker blocks 12.9% of clean calls (values the context genuinely lacks, e.g. a `receiver_id`).
**Exploratory, not registered (31 errors):** the checker and the judges catch different errors. With Opus: both 7, checker only 11, judge only 7, neither 6; union (checker OR Opus) detects 80.6% at 15.1% false blocks (Sonnet union 74.2% at 16.1%, Haiku 71.0% at 20.4%). Overlap with the Nemotron judges was not computed. This is the first evidence for a complementary cascade; it needs more data before it is a claim.



## 15. Real self-consistency as the ask trigger (Stage 2.3; run 2026-11-02; development data; Deviation 15)

## 17. Shift and guarantee study on real scores (Stage 2.5; 2026-11-02; development data; Deviation 16)

Score = deterministic checker's grounding score (the only score defined on every dataset). **(A) Transfer of a threshold (nominal alpha 0.10, plain conformal, ask rate on the target's correct calls; share of 1,000 draws within alpha):** BFCL->fcrb 1.9% (89%), BFCL->AgentHallu 1.0% (100%), BFCL->MCP-Atlas 2.4% (89%); fcrb->anything about 0% (never asks); **AgentHallu->BFCL 11.1% (26%), AgentHallu->fcrb 14.1% (28%), AgentHallu->MCP-Atlas 18.6% (26%)**. At alpha 0.20: BFCL->fcrb 28% (2% of draws within), BFCL->MCP-Atlas 41% (1%), AgentHallu->MCP-Atlas 55%.
Reading: **shift breaks the guarantee in one direction only**: a threshold calibrated on a cleaner dataset (AgentHallu, where 87% of correct calls are fully grounded) over-asks on noisier ones (up to 5.5x the budget at alpha 0.20); a threshold from a noisier dataset is conservative and asks almost nothing, i.e. it keeps the budget by losing detection (wrong calls caught about 0-4% at alpha 0.10). So "6 of 6 shift conditions violated" (branch `update1`) is not what we measure: of 27 transfer cells at plain conformal, violations (share within alpha below 90%) occur mainly for AgentHallu-as-source and for alpha 0.20.
**(B) Recalibration on n target correct calls (alpha 0.10; mean held-out ask rate; share of draws within alpha, plain / Clopper-Pearson):** AgentHallu n = 25: 3.8% (93%) / 0.0% (100%); n = 50: 7.9% (65%) / 0.7% (94%). BFCL n = 100: 5.9% (65%) / 4.9% (69%); n = 500: 5.4% (68%) / 4.7% (72%). fcrb n = 100: 0.5% (97%) / 0.0%. MCP-Atlas n = 500: 0.0% (100%).
Reading: the marginal guarantee holds on average but, at n = 50-100, only 65-77% of calibration draws stay within the budget (the calibration-conditional gap); the Clopper-Pearson rule lifts this to 94% on AgentHallu but costs detection, and on BFCL it stays near 70% because calls of one test case are correlated and ties dominate. More calibration calls (n >= 200) mostly stabilise the mean, not the per-draw guarantee.
Caveats: weak score with heavy ties (fcrb AUROC 0.55) so detection is near zero on several cells; AgentHallu has only 93 correct calls; BFCL calls are 30 models x 200 cases; development data. This study does not use the disagreement-based ask score, which exists only on BFCL.

## 21. MCP-Atlas: strict false-block rate of the deterministic checker (Stage 2.4; 2026-11-04; development data)
`benchmarks/mcpatlas_false_block.py` -> `benchmarks/mcpatlas_fbr_dev.json`. Data: 2,423 reference calls of 500 MCP-Atlas tasks (all clean, CC BY 4.0), premise = the task text only. Checker: `check_arguments`, strict (a call is blocked if any argument is UNGROUNDED).
Result: **68.8% of all calls are blocked** [66.9, 70.6]; 78.8% of the 2,114 calls with arguments; **41.7% [36.7, 46.9] of the 357 first calls of a task** (premise is the only possible evidence); 86.3% of the 1,757 later calls (their values come from earlier tool outputs the premise does not contain). The most blocking argument names: `query` (244 of 463), `base_id` (201 of 201), `database` (184 of 184), `path`, `table_name`, `code`, `collection`, `value`.
Reading (examples checked by hand): blocked first-call values are mostly legitimate derivations: a date range from "november 2024" (`2024-11-01` to `2024-11-30`), page-size defaults (`max_results` 50, `maxResults` 1000), a search query rewritten from the question, a reformatted address. Later calls use identifiers (`base_id`, `database`, `table_name`) that only the system state can supply. So on real MCP traffic the strict context checker is unusable on its own (about 40% false blocks on the easiest calls, 86% on later ones). It supports the thesis rather than weakening it: the evidence the checker sees (the user's words) is not what decides the value; derived values need the tool contract (defaults, ranges) and identifiers need system state or tool outputs. It also shows that the 12% false-block rate on AgentHallu (BFCL-style function calls whose values come from the task text) is specific to that kind of data. A deployable version needs: contract-derived defaults and date-range expansion, query-paraphrase tolerance, and tool-output memory (E3). Not a threshold-tuning problem: conformal calibration at 10% would set the threshold so low that nothing is blocked.
