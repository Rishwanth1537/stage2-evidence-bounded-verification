# Pre-registration: argument-grounding verifier vs LLM judges

Frozen on: 2026-10-09, **before any LLM judge has been run on any ArgGround-Bench case**.
Any later change must be added to the "Deviations log" at the bottom with a date and reason; the original text must not be edited.

## 1. Question
Does a deterministic, calibrated argument-grounding stage (optionally followed by an LLM only for uncertain calls) justify itself against LLM judges, on accuracy, cost/latency, robustness, determinism, error independence, and calibration under shift?

## 2. Hypotheses and decision rules
Identical to H1 to H6 in `review/RESEARCH_PLAN.md` section 3 (copied here by reference; that table is part of this registration).
Multiple comparisons: Holm correction across H1 to H6. All hypotheses are reported whether or not they are supported.

## 3. Systems
S0 always-allow / always-block; S1 exact string match; S2 type-aware argument grounding (`server/pipeline/arg_ground.py`, `FUZZY = 0.88`, `tau` as stated below); S3 whole-call DeBERTa NLI; S4 MiniCheck flan-t5-large; S5/S6 open-model judges run on Kaggle GPU; S7/S8 hosted judges through Groq and NVIDIA OpenAI-compatible endpoints (model ids recorded at run time from the provider's model list); S9 cascade S2 then one judge; S10 judge with 3-vote self-consistency.

## 4. Judge prompts (frozen)
`benchmarks/judge_prompts.py`, prompt hash **9b59ae0a3fa5384a** (variant 0 main; variants 1 to 4 only for H4). Temperature 0. Two fixed few-shot examples written for this study (not from any benchmark file). Unparseable replies count as misses.

## 5. Data and splits
- D1 ArgGround-Bench from Glaive v2 (`benchmarks/make_argground_bench.py --pages 40 --seed 5`); dev/test split by conversation premise with seed 11 (`split_cases` in `benchmarks/eval_argground.py`).
- D2 to D4 (Hermes function-calling v1, ToolACE, BFCL multi-turn) built with the same recipe; same split rule; builders committed before running judges.
- N1 natural-error set: calls produced by open instruct models at temperature 0.7 to 1.0 on D1/D4 prompts; a call is an **error** iff some argument value differs from the gold value after normalisation (case, whitespace, number formatting, ISO date/time equivalence, currency code/name); a call is **genuine** iff all argument values match gold. Labels are therefore automatic; a manual audit of at most 100 sampled "errors" estimates label precision (single annotator, no inter-rater claim).
- N2 injection-robustness set: 5 families x 500 cases drawn from the D1 test half.

## 6. Analysis rules
- Primary metrics: false-block rate (FBR), detection rate, balanced accuracy; **comparisons at matched FBR** (within 1 point), otherwise both operating points are shown.
- Bootstrap 95% CIs resampling conversations (>= 1,000 resamples); exact McNemar for paired comparisons; H1 non-inferiority margin 2 points (one-sided 95%).
- No prompt wording, threshold, `tau`, or model choice is selected using test-half results. Dev half only.
- Each final configuration is evaluated on the test half once; every additional run is reported.
- Cost/latency: tokens and wall-clock per call on the same machine class, p50 and p95; dollar figures only from prices supplied by the user.

## 7. Known limitations stated in advance
Injected errors are synthetic substitutions; the public conversations are LLM-generated; the exact-match baseline is our own reimplementation; hosted-model behaviour can change between runs; free-tier rate limits may force sub-sampling (the sample is seeded and identical across systems).

### Amendment 12b (2026-10-30, before any test run): H-A2 reworded
H-A2 as first written ("realised ask-rate on correct calls <= alpha in at least 90% of 1,000 conversation-level re-splits under the finite-sample conformal rule") is unattainable by design: split conformal is a MARGINAL guarantee and, on dev data (BFCL, 5,427 calls, 30 models), plain split conformal keeps the mean ask-rate at target (0.049, 0.097, 0.192 for alpha 0.05, 0.10, 0.20) but only 57 to 62% of individual splits stay within alpha. Replacement: report (i) the marginal rule, (ii) a calibration-conditional rule that treats the TEST CASE as the unit (30 models answer each case, so calls are not independent: a call-level Clopper-Pearson bound reached only 62 to 72% of splits), using a percentile bootstrap over test cases, with H-A2: realised ask-rate <= alpha in at least 90% of 1,000 re-splits for the cluster-aware rule, and report the detection that this guarantee costs. The strict cluster Hoeffding bound is also reported (it certifies nothing at alpha <= 0.10 with about 100 calibration cases). Dev numbers already seen: bootstrap rule within alpha in 99.5 to 100% of splits, wrong calls caught 14% / 33% / 61% at alpha 0.05 / 0.10 / 0.20 (plain rule 49% / 65% / 85%).

### Deviation 23 (2026-11-10): E2 — Class-conditional (Mondrian) conformal ask-rule (registered before any run)

Experiment: Stage 3 candidate E2 from `review/PAPER_PLAN_V2.md` section 22. The ask-policy from Stage 2.3 uses a single global conformal threshold tau calibrated on all correct calls. E2 replaces this with one threshold per decidability class of the wrong argument: `E1_conversation` (a value the conversation decides) and `E2_contract` (a value the tool definition decides). The intuition is that the peer-disagreement signal is stronger for one class than the other; a per-class threshold lets the policy use a tighter budget on the class where the signal is weaker.

Pre-set hypothesis:
- **H-E2**: At alpha = 0.10 and an equal overall ask-rate on correct calls, the Mondrian (per-class) thresholds catch at least 5 points more strong errors than a single global threshold, with the share of splits within alpha not lower than the global rule by more than 5 points.
Kill rule: if the class split leaves fewer than 30 correct calls per class after train/test splitting, the class-conditional rule is underpowered and E2 is reported as underpowered / negative. If the gain is less than 5 points AND the confidence interval includes 0, E2 is reported as not supported.

Data: BFCL strong errors (4,996 calls, 255 strong-error calls); scores: peer-disagreement (consensus), self-consistency is not available per class. Decidability class per call: a call is E2_contract if at least one of its wrong arguments is labelled E2_contract in `decidability_dev.json`; E1_conversation otherwise (for wrong calls). Correct calls are pooled across classes for calibration (no class label is known at prediction time for correct calls). Splits: 1,000 random splits by test case. Calibration rule: conformal (plain) and cluster-bootstrap. Comparison: Mondrian (per wrong-call class) vs global at the same alpha.

Script: `benchmarks/mondrian_ask.py` (new). Writes `benchmarks/mondrian_ask_dev.json`. Development data only (BFCL has no holdout split separate from the ask-policy dev data already used in Stage 2.3). No test half is loaded.

### Deviation 21 (2026-11-07): ORACLE_EXACT tier redefined to separate genuine contract violations from coercible type mismatches
Trigger: In Prompt 5B, 40 of 315 clean DeRef fcrb dev calls (12.7%) failed ORACLE_EXACT checks. A detailed audit revealed that 34 of these 40 calls failed due to implementation strictness (explicit null for optional parameters, numeric strings for integer/numeric fields, boolean-like strings, case-insensitive enum matches, or undeclared keys where additional properties are not forbidden), rather than unambiguous schema violations.
Change: ORACLE_EXACT tier redefined to separate genuine contract violations (omitted required parameters, undeclared keys when additionalProperties=false, unparseable wrong types, enum mismatches after case-insensitive check) from COERCIBLE type mismatches (explicit null for optional parameters, parseable numeric strings, boolean strings, case-insensitive enum matches).
Scope: Motivated strictly by examining dev-split false blocks. No locked split or test split was loaded, evaluated, or touched. Both the old policy (`legacy_strict`) and the new policy (`coercible` tier) are retained in the codebase and evaluated side by side in all reported tables.
